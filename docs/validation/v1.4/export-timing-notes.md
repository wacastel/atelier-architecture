# Offline H.264 export timing

The first 56-second night export decoded successfully but contained 1,341 frames instead of the expected 1,344 at 24 fps, with one presentation-timestamp gap. The corresponding first four-minute export contained 5,757 rather than 5,760 frames. Both processes had been suspended with SIGSTOP while asynchronous encoding was active. [Preserved cadence failure](export-first-cadence-failure.json). The localized gap is consistent with a pause-related encoder interruption, but that cause is not established by the file alone; it must not be presented as a confirmed VideoToolbox defect.

Inspection also found a documented configuration omission: the exporter selected H.264 High AutoLevel without specifying its expected source rate. Apple's [AVVideoExpectedSourceFrameRateKey documentation](https://developer.apple.com/documentation/avfoundation/avvideoexpectedsourceframeratekey), also present in the installed SDK's `AVFoundation/AVVideoSettings.h` discussion for that key, says the hint should be supplied with AutoLevel profiles and warns that omission can require frame dropping to meet bitstream constraints. It configures the encoder; actual presentation timestamps still determine the video timeline.

The exporter now supplies `AVVideoExpectedSourceFrameRateKey = fps` and explicitly sets [kVTCompressionPropertyKey_RealTime](https://developer.apple.com/documentation/videotoolbox/kvtcompressionpropertykey_realtime) to false. Apple's `VideoToolbox/VTCompressionProperties.h` recommends false for offline compression, where frame time is independent of elapsed wall time. `AVVideoCompressionPropertiesKey` explicitly accepts VideoToolbox compression property keys. The existing `expectsMediaDataInRealTime = false`, exact integer frame timestamps, readiness checks, append-result checks and awaited finalization remain in place.

Frame reordering retains the encoder default. Apple's [AVVideoAllowFrameReorderingKey](https://developer.apple.com/documentation/avfoundation/avvideoallowframereorderingkey) describes a compression-quality and resource tradeoff; disabling it is not a documented guarantee against missing output frames. [AVVideoAverageNonDroppableFrameRateKey](https://developer.apple.com/documentation/avfoundation/avvideoaveragenondroppableframeratekey) concerns reference-frame dependencies and temporal scalability during decoding, rather than guaranteeing retention of every appended input frame, so it is not added as a substitute for output validation.

A successful append accepts an input buffer, and successful writer finalization alone does not prove exact output cadence. Fresh exports are run sequentially without process suspension and checked for complete decoding, exact expected frame counts and one presentation timestamp per intended frame interval. Earlier affected files and their reports are preserved as failed cadence proofs rather than silently treated as valid final demos. Renderer kernels and motion-reconstruction validation are unaffected by this export configuration change.

The reusable [video timing validator](../../../scripts/validate-video-timing.py) executes both FFprobe frame/timestamp inspection and FFmpeg complete decoding. It passes the new [144-frame smoke export](export-smoke-cadence.json), while correctly rejecting the original [three-frame gap](export-cadence-negative-control.json).
